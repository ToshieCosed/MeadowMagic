# Minecraft compatibility layer — standing rules (branch `mineCompatibility`)

## The isolation rule
Anything added for Minecraft compatibility exists **only while connected in Minecraft compat mode**
(`window.__mp.mode === 'minecraft'`). It must never become a mechanic in single player or on a Strata server:

- Compat blocks, items, entities and their tables are **registered when a compat session starts and removed when it ends**. They are not part of the normal load-time tables.
- Compat block ids use the range **8192–65535**. Ids 0–6240 are Strata's; 6241–8191 stay free for Strata.
- Compat content is never added to: `B` permanently, recipes, crafting/creative inventory, item lists (`ITEMS`), world generation, mob spawning, or saves.
- Compat worlds are server-owned. They are not saved as Strata worlds, so no compat id can reach a Strata save.
- Anything the client has no model for (fish, phantoms, ...) is **skipped at the protocol layer**: no entity is created, no visual is processed.
- Strata-only features never need the compat layer, and the compat layer never needs to change Strata behaviour.

## Checks done (2026-11-05)
- Strata uses block ids up to 6240 (2205 defined). Ids are `Uint16` in chunks, so 65535 is the ceiling.
- Several per-id typed arrays were sized 8192 (`LOPQ`, `LATT`, `WATERY`, `LAVAID`, `PACK.has/x/tint`, `MAT_OF`). They are now 65536 so compat ids are addressable. Capacity only; no behaviour change.
- A block registered late with `def()` at id 9001 meshes and renders with no errors, and does not appear in `ITEMS`.
- **An id with no `BLOCKS[id]` entry crashes meshing** (`Cannot read properties of undefined (reading 'btint')`). The protocol layer must therefore map every incoming id to a registered block (a placeholder, or air) before it reaches the world.
- Minecraft block *states* are far more numerous than Strata block ids, so the compat table maps state -> compat id on demand rather than pre-registering everything.

## Build order
1. Compat gate + late registration/unregistration helper, block/entity tables behind it.
2. WebSocket relay program (browsers cannot open raw Minecraft TCP) + handshake/login.
3. Chunk decoding.
4. Other players: see them move, sync your own position.

## Stage 1: login + chat (protocol 47 .. 775)
- `src/mc/mcclient.js` is the protocol client (handshake, login, encryption via the relay, configuration phase from 1.20.2, keep-alive, chat both ways, resource-pack auto-accept, NBT text components from 1.20.3). Packet ids come from `src/mc/ids.json`, generated by `tools/mctest/gen_ids.mjs` from the minecraft-data package; `python3 tools/embed_mc.py` embeds both into `src/strata.html`.
- Tests (dev only): `cd tools/mctest && npm i && node test-mcproto.mjs` logs in and chats on 28 versions against minecraft-protocol offline servers through the real relay; `node test-page.mjs` drives the page UI.
- Not covered yet: signed chat (servers with enforce-secure-profile reject unsigned player chat on 1.19.1+; commands work), SRV lookups (give host:port), world/blocks/entities, 26.2+ (no packet data yet).
- The in-game screen is a blank sky; nothing in it touches the Strata world.

## Stage 2: protocol 47 (1.8) world, blocks and entities
- Chunks (`map_chunk`, `map_chunk_bulk`), `block_change`, `multi_block_change`, server position, entity spawn/move/teleport/destroy are decoded in `mcclient.js` and handed to `src/mc/engine.js`, which builds a Strata world (`gen: 'mcompat'`, 2048x2048x256, coordinates offset so the spawn lands mid-world) fed from the server.
- Blocks: `src/mc/blocks18.json` (made by `tools/mctest/gen_blocks18.mjs`) maps every 1.8 id/meta to a flat-colour look. A few map to existing Strata blocks (grass, dirt, stone, sand, water, lava, leaves, glass, plants); the rest are registered late as ids 8192+ and removed on disconnect. Slabs and stairs are full cubes for now; doors, ladders, rails, signs, buttons, carpet, snow layers and vines are not drawn.
- While a compat world is active the engine disables: mob AI and spawning, growth, decay, health, fluid flow, mining and saving (all restored on disconnect). Compat mobs live in a separate `__cmobs` list.
- Entities: pig, sheep, cow, chicken, horse, wolf, spider, zombie, skeleton, slime, bat and other players (generic humanoid) are drawn; everything else is skipped at the protocol layer.
- Our position is sent every 50 ms with Strata's own physics. Not yet: breaking/placing blocks, day/night sync, name tags, inventory, other versions.
- Test: `tools/mctest/test-world18.mjs` (needs `npm i` in `tools/mctest`) serves real 1.8 chunks and entities to the page, checks decode, meshing, entities, block change, and that disconnect restores the engine.

## Stage 3 (1.8): interaction, inventory, survival
- Blocks map to Strata's own stairs/slabs/doors/gates/fences/ladders/rails/plates/wool/carpet where equivalent (no duplicate renderers); the rest are compat blocks (ids 8192+).
- Breaking/placing are server-authoritative: `mineBlock` sends `block_dig` (start+finish) and `tryInteract` sends `block_place`; the world changes only on the server's `block_change`.
- Window 0 is mirrored into Strata's hotbar/inventory/armor (tools and armor map to Strata items, else generic compat items). Clicking squares sends `window_click`; the UI updates from the server's `set_slot`.
- Hearts follow `update_health`; game mode follows login/`game_state_change`; auto-respawn on death. Hotbar sits at the bottom in compat mode.
- Not yet: buttons, signs, trapdoors, levers, attacking entities, tool-speed tuning.

## Stage 4 (1.8): mobs, interactables, items, knockback
- Tapping a mob sends `use_entity` (attack); hurt flashes follow `entity_status`. More mob types map onto Strata mobs (creeper/enderman -> zombie/walker, ghast/blaze -> demon, villager -> lost, ...).
- Trapdoors use Strata's; buttons and levers are compat shape blocks (state from the server; tapping sends `block_place`). Signs become Strata sign decor from `update_sign` (orientation guessed from neighbouring blocks).
- Items with no Strata equivalent become compat items (category `compat`) with a generated icon (tinted gem + initials). Slot tooltips show item names; holding/selecting shows the name above the hotbar.
- Knockback: `entity_velocity` for the player's own entity is applied to Strata's player; damage flashes the hurt overlay.

## Stage 5 (1.8): real mining timing, drops, view range, chat
- Break time uses Minecraft's formula (hardness, tool tier/speed, harvest rule) so Strata's 10-stage crack overlay matches vanilla. A dig is started (`block_dig` 0) when you start mining a block, aborted (1) if you let go/switch, and finished (2) when the bar fills; the world changes only on the server's `block_change`.
- Dropped items are server entities (`spawn_entity` type 2 + `entity_metadata` slot): shown with Strata's drop renderer, moved by server updates, picked up by the server (`collect`).
- View radius raised to 8 chunks (the server may still cap it); fog follows.
- Own chat: if the server doesn't echo it back within ~2s it is shown locally.
- Not yet: other players' crack animations (`block_break_animation`), item merge/despawn visuals, tool durability.

## Stage 6 (1.8): field fixes
- Android: `onShowFileChooser` so file inputs (resource packs, skins, MIDI, images) open the system picker.
- The player is held in place until the chunk under them has arrived (max 8 s) so they don't fall through unloaded ground and get rubber-banded/hurt.
- HUD coordinates show the server's coordinates; throw (Q / button) sends `block_dig` 4/3 so the server spawns the item; touch controls moved above the bottom hotbar; chat log sits below the top controls.

## Stage 7 (1.8): feel
- The server owns hearts and hunger: Strata's local regen/decay is off in compat, which also stops the permanent red "hurt" tint (local regen made the client HP exceed the server's, so every health packet looked like damage).
- Dropped items: the drawn item glides toward a dead-reckoned server position (gravity 32 b/s²), so throws are smooth.
- Sounds: break/place sounds on server-confirmed block changes, material per Minecraft block; the pack sound lookup now also knows the 1.9+ layout (`block/<material>/break|place|hit|step`, `entity/item/pickup`, ...). Packs imported before this need re-importing to pick up the new sounds.
- Cracks: Minecraft's `destroy_stage_0..9` from the resource pack (both `textures/blocks` and `textures/block`), else a built-in set, drawn per pixel on every face.
- Pickup feed (+items list) shows again in compat (on the server's `collect`), and has a settings toggle (also in plain Strata).

## Stage 8 (1.8): survival basics
- `explosion` packets remove the listed blocks, add knockback, play a boom; `named_sound_effect` is mapped to Strata/pack sounds (block dig/step, mob voices, hurt, bow, explosions, doors...).
- More mob types map onto Strata mobs (giant, magma cube, dragon/wither, endermite, guardian, snow golem, iron golem).
- Strata's wall-climbing is OFF in Minecraft mode (setting: "Wall climbing in Minecraft mode"), and horizontal speed is capped to Minecraft's (walk 4.4, sprint 5.7, sneak 1.4 b/s) with dash disabled, so servers stop rubber-banding sprinting.
- Not yet: other players' bodies (name tags, armor, held items, poses via `entity_equipment`/metadata), arrows and other projectiles, textured 3D drop/hand items.

## Stage 9 (1.8): other players
- Players are drawn with Strata's own skin renderer: skin from the `player_info` `textures` property (fetched directly, falling back to crafatar by UUID; if both fail the default Strata skin is used), slim/classic arms, walk/sneak/sprint/swing poses (`entity_metadata` flags, `animation`), armour and held item from `entity_equipment`. Your own skin is taken from your own `player_info` entry and restored on disconnect.
- Name tags: small DOM labels above every player (and you, in third person), coloured per name, fading with distance. Pause menu: "Player name tags (Minecraft mode)".
- `loadSkin`/`skinUpload` now take an optional target so any number of skins can exist.
- Not yet: skin fetching through the relay (if both direct sources are CORS-blocked), capes, other players' crouch-hit boxes, mob models beyond Strata's own archetypes.

## Stage 10: generic fallback mob (compat only)
Server mobs Strata has no model for (ghast, blaze, spider, etc.) render as the zombie model with a speckled green texture generated at runtime (`ENT.mcgeneric`). It is removed on disconnect and never exists outside compat mode. Compat mobs are now drawn by `drawSkins` through `window.__cmobs`.

## Stage 11 (1.8): mob models, held items, projectiles, hunger (compat only)
- Mobs Strata has no model for now use Minecraft 1.8's own model geometry, so resource-pack entity textures wrap onto them the way the horse/spider/cow skins do: creeper, ghast, blaze, silverfish, endermite, magma cube, witch, iron golem, snow golem (with a pumpkin), ocelot, rabbit, guardian, wither and ender dragon. Variants reuse Strata's models with their own texture: mooshroom (cow), cave spider (spider, 0.7x), zombie pigman (zombie), wither skeleton (skeleton, 1.2x, from metadata), giant (zombie, 6x).
- These are `mc_*` types in `src/mc/engine.js` (`CM`). `start()` registers their `MOB` entries and `window.__cmModel` (asked first by Strata's `modelFor`); `stop()` removes both, so none of them exist outside compat mode. Their pack files are listed in `ENT_FILES`, so packs imported before this need re-importing to pick them up.
- Without a pack texture: types with a Strata equivalent fall back to Strata's own model (mooshroom -> cow, magma cube -> magma slime, ...); the rest get a texture generated in the mob's colours, with a face.
- Spawn metadata is now read (baby, skeleton type, slime/magma size).
- Held items: `entity_equipment` slot 0 on mobs is drawn with Strata's item renderer in the right hand. Skeletons hold Strata's bow and raise both arms to aim when armed; zombies/pigmen hold their swords.
- Projectiles: arrows (object 60) and fireballs (63, 64) become entries in Strata's own `arrows` list and are drawn by Strata's arrow/fireball renderer. Their flight is simulated client-side (vanilla physics: drag, gravity, sticking in blocks) and corrected by server position updates; Strata's own `stepArrows` is off while connected.
- Hunger: a row of drumsticks under the hearts follows the server's `update_health` food value (right to left, half shanks), hidden in creative.
- Fixes: pack zombie arms/legs (the right limbs sampled zombie.png's empty lower half; they now mirror the left ones like vanilla's biped) and the built-in zombie/skeleton hands z-fighting with their sleeves.
- Test (dev only): `tools/mctest/test-mobs18.mjs` spawns every 1.8 mob type, arms them, fires arrows and sends food; `PACK=1 CLOSE=1` paints each model's box faces in distinct colours to check the UV wrapping and screenshots each mob.

## Stage 12 (1.8): field fixes
- Disconnects: the client now sends `MC|Brand` "vanilla" after joining, keeps sending movement every tick even with a menu open (it stopped while the inventory/pause was up), and acknowledges refused window clicks (`transaction`). A drop without a reason now says how long you were connected, when the server last sent anything, when the last keep-alive came, and whether the app was in the background, so the cause can be told apart (server silence vs. app paused vs. relay lost).
- The Chat/Disconnect bar and chat log hide while the inventory or another game panel is open, so they can't cover it.
- Plants map to Strata's own: sugar cane, tall grass/fern/dead bush, all 1.8 flowers, saplings, wheat/carrots/potatoes by growth stage, and double plants (both halves).
- Item icons: a pack's `items/*.png` is now imported in full, and compat items use their 1.8 texture name (from minecraft-assets, names only, in `items18.json`) with damage variants (dyes, coal/charcoal, fish, golden apple, potion bottles). Without a pack texture they get a drawn icon by kind (meat, dust, bottle, ball, rod, book, disc, seeds, gem) in a fitting colour instead of letters.
- Sun (Strata and compat): the disc, glow and shafts are drawn at the far plane with depth testing, before the first-person hand clears depth, so blocks hide the sun. Test: `tools/tests/phase25_sun_occlusion.py`.

## Stage 13 (1.8): server inventories, crafting, time, movement
- Inventory: Minecraft mode has its own inventory screen (`#mcInv`) where every slot is the server's: the 2x2 crafting grid + armour from window 0, and container windows from `open_window` (crafting table 3x3, furnace with burn/cook progress, chests and other grids, brewing stand, enchanting table, anvil, villager, dispenser/dropper, hopper). Clicks are `window_click` (Place 1 = right click, Quick move = shift-click); closing sends `close_window` so the server returns grid items. Strata's recipe book, crafting grid and item catalog are never shown in this mode. Creative: a catalog of 1.8 items (with colour variants) that sets slots with `set_creative_slot`.
- Time: `update_time` drives Strata's clock (24000 ticks = 10 min day + 10 min night; a frozen server clock stays frozen). Skip-time only works in creative, as a `/time set` command the server must accept; in survival it says the server controls the time. Day/night length sliders and Save & quit are hidden in this mode.
- UI: the top bar is gone in a live world; chat is a round button on the left edge, Disconnect is in the pause menu, and the bar returns when the connection drops so the reason shows.
- Movement: auto-step is limited to vanilla's half block (the 1-block auto-step made servers rubber-band you).
- The sugar cane item is Strata's sugar cane (placeable, right icon).

## Stage 14 (1.8): world details
- Torches use Strata's floor/wall torches by metadata, so wall torches lean against their wall. Redstone torches (on/off) are compat-only blocks reusing Strata's torch renderer with red flames (`flame`/`flame2` on the block); lit ones give a little red light.
- Redstone dust (brightness from power), repeaters (delay torch position), comparators, tripwire hooks and tripwire, and daylight sensors are compat-only shape blocks. Redstone ore/lamps/blocks were already cubes. Rails (incl. detector/powered/activator) stay Strata rails.
- Beacon beams: beacons in loaded chunks are tracked; a beam is drawn when the block under is iron/gold/diamond/emerald (only the top layer is checked) until it hits an opaque block.
- End crystals (object 51): spinning nested cubes on a base.
- Paintings (`spawn_entity_painting`): placed with vanilla's offsets; the picture comes from the pack's `painting/paintings_kristoffer_zetterstrand.png` (now imported) or a framed placeholder with the painting's name.
- Note blocks: the server's `note.*` sounds play through a small synth (harp, bass, drum, snare, hat) with a coloured note particle by pitch.
- Moon: at night (server time) a pale moon crosses the sky in first-person/close views, hidden by blocks like the sun.
- Not in 1.8: shulker boxes (1.11) come with later protocol versions.

## Stage 15 (1.8): inventory that keeps up
- In 1.8 the server does not send back the slots a normal click changes (the client is expected to apply the click itself). The compat screen now applies every pickup/put-down/swap/merge/split locally the moment you tap, exactly like `Container.slotClick` mode 0, and sends the click with the item that was in the slot so the server accepts it. Taking from a crafting output also uses up one of each grid item locally; the server sends the next result.
- "Send across" (shift-click) is too rule-heavy to predict, so it goes out with a deliberately different item: the server does the move, rejects the guess and resends the whole window. Further taps wait for that answer (max 2.5 s) so none are lost.
- Tap modes: "whole stack", "one item", "send across"; press and hold any slot for one item. Labels and the Holding line use Minecraft's own item names.
- The bag/inventory buttons were bound to Strata's original inventory at load time, which showed Strata recipes in Minecraft mode; they now call whichever inventory is active.
- Test harness note: under SwiftShader the page is too slow to answer the test server's keep-alives in time, so that server kicks after ~30 s; keep-alive replies themselves are correct.

## Stage 16: Strata inventory taps; 1.8 enchanting, potions, books, boats (compat)
- Strata's inventory (panel, chest, crucible) gets the same tap modes as Minecraft mode — whole stack / one item (pick up half, put down one) / send across (hotbar ↔ backpack ↔ chest) — and press-and-hold for one item. The split layout has ½ and ⇄ tool toggles (its own hold-to-drag stays).
- Enchantment shimmer on slots (Strata enchantments and grimoires, and Minecraft items whose NBT has `ench`/`StoredEnchantments`).
- Potions: one compat item per effect and splash, named ("Potion of Swiftness"), tinted from the pack's potion_overlay (or a drawn bottle in the effect colour).
- More 1.8 blocks use Strata's own: bookshelf, cobweb, mushrooms and mushroom blocks, jukebox, iron bars, melon, mycelium, lily pad, sea lantern, packed ice, snow block. Compat shapes: enchanting table, brewing stand, anvil (by facing/damage), cauldron (water level), hopper, end portal frame, dragon egg.
- Enchanting table: a floating book that opens when you are near and glyph particles drifting in from bookshelves two blocks away. Enchant screen: three choices with lapis/level cost and the server's clue (`enchant_item`). Anvil screen: rename field (`MC|ItemName`) and the level cost. XP level comes from `experience` (Strata's XP bar shows it). Anvil/villager/enchant/brewing/furnace outputs resync from the server.
- Potion effects on you (`entity_effect`/`remove_entity_effect`) show as a column of icons (from the pack's gui/container/inventory.png when imported, else coloured badges) with time left.
- Books: tapping the air with a book & quill or written book opens Strata's ForgeWrite. § colour/format codes become colours, bold, italic, underline, strike; on Done/Sign the pages go back as § text (colours snapped to Minecraft's 16) via `MC|BEdit`/`MC|BSign`.
- Using items in the air (eat, drink, throw pearls/snowballs/eggs/bottles, bow, fishing rod) sends the 1.8 use-item packet.
- Boats and minecarts (objects 1/10) are Strata vehicles moved only by the server; tap one to ride (`use_entity` interact). While riding, look + `steer_vehicle` go out instead of positions; Crouch gets off. Fishing floats (90) are drawn with a line from your hand.
- Ice and packed ice are slippery in Minecraft mode; prone swimming (a 1.13 feature) is off there.
- Fix: `OVR` listed some functions twice, so the second save overwrote the original with the compat version and leaving a server left tapEntity/stepHealth/stepDecay broken until reload. Saves and restores now use each name once.

## Stage 19: plugin and server features, elytra, shields, recipe book (1.8 - 1.12.2)

Everything here exists only while connected in compat mode and is removed on disconnect.

- **Holograms and custom names**: entity metadata 2/3 (custom name, name visible) on mobs, players and armour stands. Invisible (flag 0x20) and marker stands draw no body, so plugin holograms show as floating text. Small stands draw at half size.
- **Teams**: `scoreboard_team` / `teams` prefix, suffix and colour on name tags and the tab list; `nameTagVisibility: never` hides the tag (NPC plugins). Tab list display names (`player_info` action 3) and the below-name scoreboard slot. NPC player entities keep their name after the server removes them from the tab list.
- **Chat**: `run_command` / `suggest_command` click events and `show_text` hover text. Command suggestions use `tab_complete` and appear above the chat box as you type a `/command` (Tab picks the first).

## Stage 20: Forge servers (1.12.2) and mod ports

Turn on **Forge server (1.12.2 mods)** in the connect screen. Everything here exists only in a Forge session.

- **Joining**: Strata reads the server's mod list from its status ping, adds the `\0FML\0` marker to the handshake, and answers the FML handshake (protocol 2: `REGISTER`, `FML|HS` hello / mod list / registry data / acks, `FML|MP` multipart). The server's registries (`minecraft:blocks`, `minecraft:items`, `minecraft:entities`, ...) map the world's ids to names. Modded ids fill gaps anywhere in the table (Solar Flux gets 253), so blocks and items are recognised by registry name.
- **Mod jars**: "Import mod jars" takes `.jar` files or a `.zip` of a mods folder and stores, per mod: block/item textures, blockstate + model JSON resolved to [side, top, bottom] textures (Forge `forge_marker` blockstates too) and box shapes from model elements, item textures, and `en_us.lang` names. They are layered over the player's pack for the session. Without jars, modded blocks are plain colours with readable names.
- **Modded entities** arrive through FML's own spawn message (channel `FML`, discriminator 2) and show as the stand-in mob with the entity's name. Mod container screens arrive as FML `OpenGui`; the slot count comes with the window's items.
- **Ports** (`PORTS` in engine.js): a mod's client half, keyed by mod id: `block(name, meta)` for blocks the mod draws in code, `payload[channel]` for its network messages, `gui(W, box)` for extra screen content, `tap` / `use` for client-opened screens.

### 20d — Warp Book (1.12.2-3.3.4)
- Channel `warpbook`, with the discriminator byte assigned in registration order. Client to server: 0 is warp (int index into the book's `WarpPages` NBT list) and 1 is waypoint name (raw UTF-8, no length prefix). Server to client: 2 is the hyper waypoint table (NBT `data`) and 3 is the warp effect (bool enter, int x, y, z), which plays portal particles and sound.
- The mod opens the page list and the naming screen on the client, so the port does the same. Using a book shows its pages, read from the item's NBT; tapping a page sends its list index. Using an unbound page or potion asks for a name and sends it. In both cases the normal right click goes to the server first, so it records the held book or the page being bound. When crouching, the port steps aside so the server opens the page inventory or binds the page to the player.
- Item icons: the port's `icons` map sends layered or tinted item models to the mod's pre-coloured page textures, and potions to the vanilla bottle. Any port can supply `icons` this way.
- Tested on the real server (test-forge): naming an unbound page gives a Bound Warp Page with that name, and a book holding a page for (30, 4, 30) warps the player there.
- Fix: a right click with any modded item (not a block) now sends `use_item` (`modUse`). Before this, only vanilla usable items did, so bound warp pages and other right-click mod items did nothing. Tapping a block with one also sends the use, like the vanilla client, unless the block is modded or reacts to clicks.
- Ports can add `label(n, mc)` for item names taken from NBT; pages show the name you gave them. Custom `display.Name` names now show for every item. Ports can also add `packed()` to build icons after each pack load. Warp Book composes its pages the way the mod tints them: the paper layer plus a symbol coloured by warp type (bound is teal, player is red, hyper is green).
