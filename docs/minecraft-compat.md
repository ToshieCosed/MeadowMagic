# Minecraft compatibility layer — standing rules (branch `mineCompatibility`)

## The isolation rule
Anything added for Minecraft compatibility exists **only while connected in Minecraft compat mode**
(`window.__mp.mode === 'minecraft'`). It must never become a mechanic in single player or on a Strata server:

- Compat blocks, items, entities and their tables are **registered when a compat session starts and removed when it ends**. They are not part of the normal load-time tables.
- Compat block ids use the range **8192–65535**. Ids 0–6240 are Strata's; 6241–8191 stay free for Strata.
- Compat content is never added to: `B` permanently, recipes, crafting/creative inventory, item lists (`ITEMS`), world generation, mob spawning, or saves.
- Compat worlds are server-owned. They are not saved as Strata worlds, so no compat id can reach a Strata save.
- Anything the client has no model for (fish, phantoms, ...) is **skipped at the protocol layer**: no entity is created, no visual is processed.
- Strata-only features never need the compat layer, and the compat layer never needs to change Strata behaviour.

## Checks done (2026-11-05)
- Strata uses block ids up to 6240 (2205 defined). Ids are `Uint16` in chunks, so 65535 is the ceiling.
- Several per-id typed arrays were sized 8192 (`LOPQ`, `LATT`, `WATERY`, `LAVAID`, `PACK.has/x/tint`, `MAT_OF`). They are now 65536 so compat ids are addressable. Capacity only; no behaviour change.
- A block registered late with `def()` at id 9001 meshes and renders with no errors, and does not appear in `ITEMS`.
- **An id with no `BLOCKS[id]` entry crashes meshing** (`Cannot read properties of undefined (reading 'btint')`). The protocol layer must therefore map every incoming id to a registered block (a placeholder, or air) before it reaches the world.
- Minecraft block *states* are far more numerous than Strata block ids, so the compat table maps state -> compat id on demand rather than pre-registering everything.

## Build order
1. Compat gate + late registration/unregistration helper, block/entity tables behind it.
2. WebSocket relay program (browsers cannot open raw Minecraft TCP) + handshake/login.
3. Chunk decoding.
4. Other players: see them move, sync your own position.

## Status: menu and login (2026-11-05)
- Multiplayer -> Minecraft Compat shows a **version dropdown** (1.8.9 - 1.21.4, with protocol numbers), a **relay address** field and **Sign in with Microsoft**.
- Sign-in is a device-code login run by `tools/relay/relay.mjs`; the browser shows the code and keeps only name + UUID. See `tools/relay/README.md` (needs your own Azure client id).
- Verified against mock endpoints only. Not yet verified against real Microsoft/Mojang servers.
- Next: server join through the relay (handshake, encryption, session-server join for online-mode servers), then chunks.

## Stage 1: login + chat (protocol 47 .. 775)
- `src/mc/mcclient.js` is the protocol client (handshake, login, encryption via the relay, configuration phase from 1.20.2, keep-alive, chat both ways, resource-pack auto-accept, NBT text components from 1.20.3). Packet ids come from `src/mc/ids.json`, generated by `tools/mctest/gen_ids.mjs` from the minecraft-data package; `python3 tools/embed_mc.py` embeds both into `src/strata.html`.
- Tests (dev only): `cd tools/mctest && npm i && node test-mcproto.mjs` logs in and chats on 28 versions against minecraft-protocol offline servers through the real relay; `node test-page.mjs` drives the page UI.
- Not covered yet: signed chat (servers with enforce-secure-profile reject unsigned player chat on 1.19.1+; commands work), SRV lookups (give host:port), world/blocks/entities, 26.2+ (no packet data yet).
- The in-game screen is a blank sky; nothing in it touches the Strata world.

## Stage 2: protocol 47 (1.8) world, blocks and entities
- Chunks (`map_chunk`, `map_chunk_bulk`), `block_change`, `multi_block_change`, server position, entity spawn/move/teleport/destroy are decoded in `mcclient.js` and handed to `src/mc/engine.js`, which builds a Strata world (`gen: 'mcompat'`, 2048x2048x256, coordinates offset so the spawn lands mid-world) fed from the server.
- Blocks: `src/mc/blocks18.json` (made by `tools/mctest/gen_blocks18.mjs`) maps every 1.8 id/meta to a flat-colour look. A few map to existing Strata blocks (grass, dirt, stone, sand, water, lava, leaves, glass, plants); the rest are registered late as ids 8192+ and removed on disconnect. Slabs and stairs are full cubes for now; doors, ladders, rails, signs, buttons, carpet, snow layers and vines are not drawn.
- While a compat world is active the engine disables: mob AI and spawning, growth, decay, health, fluid flow, mining and saving (all restored on disconnect). Compat mobs live in a separate `__cmobs` list.
- Entities: pig, sheep, cow, chicken, horse, wolf, spider, zombie, skeleton, slime, bat and other players (generic humanoid) are drawn; everything else is skipped at the protocol layer.
- Our position is sent every 50 ms with Strata's own physics. Not yet: breaking/placing blocks, day/night sync, name tags, inventory, other versions.
- Test: `tools/mctest/test-world18.mjs` (needs `npm i` in `tools/mctest`) serves real 1.8 chunks and entities to the page, checks decode, meshing, entities, block change, and that disconnect restores the engine.

## Stage 3 (1.8): interaction, inventory, survival
- Blocks map to Strata's own stairs/slabs/doors/gates/fences/ladders/rails/plates/wool/carpet where equivalent (no duplicate renderers); the rest are compat blocks (ids 8192+).
- Breaking/placing are server-authoritative: `mineBlock` sends `block_dig` (start+finish) and `tryInteract` sends `block_place`; the world changes only on the server's `block_change`.
- Window 0 is mirrored into Strata's hotbar/inventory/armor (tools and armor map to Strata items, else generic compat items). Clicking squares sends `window_click`; the UI updates from the server's `set_slot`.
- Hearts follow `update_health`; game mode follows login/`game_state_change`; auto-respawn on death. Hotbar sits at the bottom in compat mode.
- Not yet: buttons, signs, trapdoors, levers, attacking entities, tool-speed tuning.

## Stage 4 (1.8): mobs, interactables, items, knockback
- Tapping a mob sends `use_entity` (attack); hurt flashes follow `entity_status`. More mob types map onto Strata mobs (creeper/enderman -> zombie/walker, ghast/blaze -> demon, villager -> lost, ...).
- Trapdoors use Strata's; buttons and levers are compat shape blocks (state from the server; tapping sends `block_place`). Signs become Strata sign decor from `update_sign` (orientation guessed from neighbouring blocks).
- Items with no Strata equivalent become compat items (category `compat`) with a generated icon (tinted gem + initials). Slot tooltips show item names; holding/selecting shows the name above the hotbar.
- Knockback: `entity_velocity` for the player's own entity is applied to Strata's player; damage flashes the hurt overlay.
